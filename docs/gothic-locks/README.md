# Gothic Remake — Замки

Русскоязычный справочник и решатель встроен в существующий сайт по адресу `/apps/gothic-locks`. Открыть его можно из раздела **«Приложения»**; каталог проектов находится по адресу `/projects`. Раздел работает в браузере, не требует регистрации, серверной базы или платных сервисов. Новые npm-зависимости для него не добавлены.

## Как пользоваться

1. Выберите лагерь или найдите сундук по имени и ориентиру. Например: «Старый лагерь» → «Сундук Скатти».
2. Выберите «Без навыка», «Обучен» или «Мастер». Выбор запоминается на устройстве. При одинаковых положениях и связях безопасная последовательность одна и та же; выбор навыка сам по себе не меняет механизм.
3. Сверьте исходные положения и связи с игрой. Пластина № 1 — **самая нижняя**, номера идут снизу вверх. Позиции — от 1 до 7, цель каждой пластины — 4.
4. Выполните текущую команду целиком, затем нажмите «Готово, следующий шаг». Повторяющиеся одиночные движения объединены, но решатель проверяет каждое промежуточное положение.
5. Полную комбинацию можно раскрыть и скопировать. Отметку «Уже вскрыт» пользователь ставит сам; приложение не связано с PSN и не узнаёт результат игры автоматически.

«Назад» и «Начать заново» изменяют только показываемый шаг, не состояние замка в игре. Если движения не совпали с ожиданием, отмычка сломалась или механизм изменился, нажмите **«Положения изменились / отмычка сломалась»**. Старый прогресс карточки сбрасывается, и прежняя инструкция остаётся скрыта до ввода нового состояния либо явного подтверждения, что все исходные позиции и связи снова совпадают.

В режиме **«Моего сундука нет»** задайте число пластин, текущие положения и направленные связи. Проверьте, увеличивает или уменьшает нажатие «вправо» номер позиции. Матрица читается так: строка — выбранная пластина, столбец — зависимая; `+` означает то же направление, `−` — противоположное, `0` — отсутствие связи. Обратная связь автоматически не добавляется. Режим подходит и для частично открытого замка.

На устройстве сохраняются навык, просмотренные карточки, отметки и прогресс карточек каталога. Они не синхронизируются между браузерами; очистка данных сайта удаляет их. Вручную введённая конфигурация пока хранится только в текущей открытой странице и после перезагрузки не восстанавливается.

## Запуск для разработки

Нужны Node.js **20.9 или новее** и npm. Минимум соответствует установленному Next.js 16; основной CI использует Node 20. В корне репозитория:

```sh
npm ci
npm run dev
```

Откройте [локальную страницу](http://localhost:3000/apps/gothic-locks). Команда `predev` автоматически подготавливает Worker и иконки. В режиме разработки Service Worker отключён; офлайн-проверку выполняйте на статической сборке.

После изменения ядра решателя во время уже запущенного dev-сервера обновите браузерные модули:

```sh
node scripts/build-gothic-locks.mjs --prepare
```

Раздел не требует API-ключей или новых переменных окружения. Настройки остальных приложений сайта сохраняют свои существующие требования.

## Проверка и статическая сборка

```sh
npm run build
npm run test:gothic
```

`npm run build` выполняет три этапа: `prebuild` создаёт ES-модули Worker и PNG-иконки, Next.js экспортирует сайт в `out/`, `postbuild` формирует полный офлайн-кеш и дополнительный `out/apps/gothic-locks/index.html`. Не заменяйте эту команду одним `next build`: при прямом вызове Next пропускаются npm lifecycle-этапы. После изменений исходников снова выполните полную сборку.

`npm run test:gothic` запускает проверки симулятора, алгоритма, каталога и PWA. В частности, проверяются границы связанных пластин, направление движения, кратчайшие пути, отдельный результат при ограничении поиска, контрольные сундуки и офлайн-ресурсы. TypeScript в Node-тестах транспилируется установленным компилятором: нативная поддержка `.ts` в Node 24 не требуется. После чистой установки сначала выполните сборку: PWA-тест использует подготовленные файлы, а при наличии `out/` также проверяет экспорт.

Для локального просмотра готового сайта без установки дополнительных npm-пакетов можно использовать **уже установленный Python 3**:

```sh
python -m http.server 8765 --bind 127.0.0.1 --directory out
```

Откройте [статическое приложение](http://127.0.0.1:8765/apps/gothic-locks/). Завершающий слеш использует созданный `index.html` и не требует правил clean URL. Остановить сервер — `Ctrl+C`. Прямое открытие HTML через `file://` для Worker/PWA не подходит; `npm start` не является способом обслуживания настроенного `output: "export"`.

Для этого сайта все URL ресурсов рассчитаны на корень домена. Перенос в подпапку требует согласованного изменения `basePath`, URL Worker, манифеста и Service Worker.

## Установка на Android и работа без сети

После разрешённой публикации откройте `/apps/gothic-locks` в Chrome на телефоне по **HTTPS**. Дождитесь надписи **«Доступно офлайн»**, затем выберите в меню Chrome «Установить приложение» / «Добавить на главный экран» либо кнопку установки на странице. Название команды зависит от версии браузера.

Проверьте установку: закройте приложение, включите авиарежим, снова запустите значок, найдите сундук и попробуйте новый ручной расчёт. Внешняя карта и ссылки на источники требуют интернета. Для локального тестирования на компьютере безопасным контекстом считается `localhost`/`127.0.0.1`; обычный HTTP-адрес компьютера в домашней сети не заменяет HTTPS на телефоне.

При обновлении подключитесь к интернету, дождитесь загрузки новой версии, закройте все вкладки и отдельное окно приложения и откройте заново. Браузер может очистить кеш при нехватке места; тогда приложение нужно открыть онлайн повторно. Подробности кеширования, хостинга и протокола проверки готовности — в [PWA.md](./PWA.md).

## Необязательная проверка в настоящем браузере

Скрипт [test-gothic-browser.cjs](../../scripts/test-gothic-browser.cjs) проверяет интерфейс, сохранения, изменённое состояние, мобильную вёрстку, Worker и перезагрузку без сети. Он не входит в обязательную установку проекта: нужен уже доступный Playwright и Chromium.

Если Playwright доступен как обычный Node-модуль и его Chromium установлен, достаточно запустить статический сервер и во втором терминале выполнить:

```sh
node scripts/test-gothic-browser.cjs
```

Поддерживаемые переменные окружения:

| Переменная | Назначение |
| --- | --- |
| `PLAYWRIGHT_MODULE` | Путь к уже установленному модулю Playwright; без неё используется `require('playwright')`. |
| `CHROMIUM_PATH` | Путь к существующему исполняемому файлу Chromium; без неё используется браузер Playwright. |
| `GOTHIC_TEST_URL` | Адрес приложения; по умолчанию `http://127.0.0.1:8765/apps/gothic-locks`. Для Python-сервера можно задать вариант с завершающим слешем. |
| `GOTHIC_TEST_OUTPUT` | Каталог скриншотов и `result.json`; по умолчанию `work/gothic-browser`. |

Пример только настройки адреса в PowerShell:

```powershell
$env:GOTHIC_TEST_URL = 'http://127.0.0.1:8765/apps/gothic-locks/'
node scripts/test-gothic-browser.cjs
```

Скрипт не устанавливает Playwright, браузеры или другие зависимости автоматически. Браузерные проверки и математическая симуляция не являются проверкой комбинаций в игре на PS5.

## Данные и ограничения первого каталога

В каталоге **20 записей с опубликованными исходными конфигурациями**. Это сведения источника, а не 20 проверок в игре: у записей `verification: 'source'`, версия игры не указана (`gameVersion: null`). Приведены Скатти и две отдельные записи Кор Галома; второй сундук сохранён как вариант источника, поскольку опубликованные исходные состояния расходятся. Недостающие маршрут, этаж или добыча оставлены неизвестными.

Русские названия переведены для поиска; полное совпадение с игровой локализацией не подтверждено. Каталог не является полным перечнем сундуков Колонии. Для непредставленного или изменённого замка используйте ручной ввод. Симулятор не моделирует прочность отмычки, последствия поломки или автоматическое изменение связей по навыку: он решает именно переданную текущую конфигурацию и исключает ходы с упором в границу.

Результаты поиска различаются явно: `solved` — последовательность найдена и проиграна симулятором, `unsolvable` — безопасная цель недостижима в этой модели, `limit` — не хватило ресурса поиска без доказательства неразрешимости, `invalid` — неверный ввод. По умолчанию время поиска ограничено 8 секундами. Большие задачи выполняются в Worker, не блокируя интерфейс.

## Как добавить замок

Добавьте запись в [catalog.ts](../../src/lib/gothic-locks/catalog.ts) с уникальным `id`. Укажите источник, его ссылку и проверенную ревизию/дату, статус проверки, известную версию игры и ориентиры. Для неизвестного значения используйте `null` или пустой массив согласно типу `LockEntry`; не заполняйте пробелы догадками. `valuable` включайте только при подтверждённом содержимом. При отсутствии конфигурации задайте `config: null`: интерфейс предложит ручной ввод.

У `LockConfig` следующий контракт:

```ts
{
  positions: [/* 4–7 целых чисел от 1 до 7; нижняя пластина первая */],
  links: [/* квадратная матрица N×N; значения -1, 0, 1 */],
  direction: 'right-decreases' // либо 'right-increases'
}
```

`links[from][to]` задаёт реакцию пластины `to` на движение `from` в сторону увеличения номера позиции. Диагональ должна содержать **0**: движение самой выбранной пластины алгоритм учитывает отдельно. Связи не обязаны быть симметричны. `direction` переводит числовое изменение позиции в физическую команду: `right-decreases` означает, что кнопка «вправо» уменьшает номер позиции; `right-increases` — увеличивает.

Не смешивайте индексы снизу вверх с нумерацией сверху вниз и не исправляйте опубликованное исходное состояние по другой базе без отдельной записи происхождения. Разные версии механизма должны быть различимы по `id`, названию/предупреждению и метаданным. Для Скатти и Кор Галома уже есть отдельные регрессионные проверки; добавьте проверку при внесении нового подтверждённого случая. Затем запустите `npm run build` и `npm run test:gothic`.

## Публикация

Изменения подготовлены локально; развёртывание на действующем сайте в рамках этой работы не выполнялось. Перед публикацией необходимо разрешение владельца.

В существующем GitHub Actions workflow отправка изменений в ветку **`main`** запускает сборку и публикацию GitHub Pages. Ручной `workflow_dispatch` также публикует сайт. Поэтому `git push` в `main` и запуск этого workflow являются действиями публикации, а не только сохранением исходников.

После согласования выпуска публикуется согласованный статический экспорт `out/` целиком, включая `_next/`, Worker, манифест, иконки и финальный Service Worker. Команда `npm run build` сама по себе ничего не отправляет на хостинг. Для размещения не нужны новые платные службы.
