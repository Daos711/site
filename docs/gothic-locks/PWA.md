# PWA: Gothic Remake — Замки

Приложение находится по адресу `/apps/gothic-locks`. Оно использует существующий статический экспорт Next.js, локальное хранилище браузера и отдельный Worker для вычислений. Учётная запись и сервер приложения не нужны.

## Запуск и сборка

В корне репозитория:

```sh
npm install
node scripts/build-gothic-locks.mjs --prepare
npm run dev
```

`--prepare` создаёт PNG-иконки и браузерные ES-модули решателя в `public/apps/`. После изменений ядра повторите команду. В режиме разработки Service Worker регистрировать не нужно: финального кеша ресурсов ещё нет.

Для выпуска:

```sh
npm run build
```

Скрипт `postbuild` должен вызывать `node scripts/build-gothic-locks.mjs`. Если сборка вызывается напрямую через `next build`, выполните этот скрипт после неё вручную. Он проверяет наличие страницы, находит её локальные JS/CSS/шрифты, раскрывает ссылки из модулей и стилей, добавляет решатель и создаёт финальный Service Worker в `out/apps/gothic-locks-sw.js`. Отчёт `out/apps/gothic-locks-precache.json` перечисляет файлы и общий размер кеша.

Публикуется содержимое `out/` вместе с `_next/`, а не только HTML нового раздела. Сборка ничего не публикует. Адрес домена, настройки действующего хостинга и разрешение на публикацию проверяются отдельно.

## Подключение в UI

Манифест: `/apps/gothic-locks.webmanifest`.

```ts
navigator.serviceWorker.register("/apps/gothic-locks-sw.js", {
  scope: "/apps/gothic-locks",
  updateViaCache: "none",
});
```

В области действия намеренно нет завершающего слеша: она включает адрес страницы без слеша и вариант со слешем. Скрипт находится в `/apps/`, поэтому специальный заголовок `Service-Worker-Allowed` не требуется. Кеш перехватывает только перечисленные ресурсы и четыре адреса этой страницы; страницы остальных приложений проходят в сеть.

Проверить завершение подготовки офлайн можно после `navigator.serviceWorker.ready`. Дополнительный протокол:

- Service Worker отправляет клиентам `{type: "GOTHIC_OFFLINE_READY"}` после успешной активации.
- Сообщение `{type: "GOTHIC_CHECK_OFFLINE"}` с `MessageChannel.port2` получает ответ `{ready: boolean, version: string}` на `port1`.

Для вычисления:

```ts
const worker = new Worker("/apps/gothic-locks-worker.js", { type: "module" });
worker.postMessage({ id: "optional-request-id", config, limits: { maxMilliseconds: 8000 } });
// Ответ: { id, result: SolveResult } или { id, error: string }.
```

Полные сторонние уведомления распространяются вместе с приложением в /apps/gothic-locks-licenses.txt. Сборка объединяет исходные vendor/Murzav-LICENSE.txt и vendor/Arminek-NOTICE.txt, сохраняет полные тексты, копирует результат в экспорт и кеширует его для просмотра офлайн.

Worker исполняет те же `solver.ts` и `simulator.ts`, что проверяются тестами. Это не отдельная копия алгоритма. Изменённую конфигурацию нужно отправлять новым запросом; отмена длительного расчёта выполняется через `worker.terminate()`.

## Офлайн и обновления

Первый запуск требует интернета. При установке Service Worker весь перечень ресурсов загружается целиком: ошибка любого запроса прерывает установку и не активирует неполный кеш. После успешной установки запуск и перезагрузка раздела используют сохранённую HTML-страницу и её ресурсы.

Версия кеша зависит от содержимого всех файлов. При выпуске новой версии сначала загружается новый полный кеш. Обновление ожидает закрытия всех вкладок и окон приложения: работающая сессия остаётся на согласованной старой версии HTML/JS/Worker. После освобождения старых клиентов новая версия активируется; удаляются только кеши с префиксом `gothic-locks-v1-`. Чужие кеши и локальные отметки пользователя не удаляются. Для обновления откройте приложение с интернетом, дождитесь загрузки, затем закройте все его вкладки и отдельное окно PWA и откройте снова. При первой установке ожидание закрытия не требуется.

Приложение не кеширует внешние сайты, карты, аналитику или CDN. Общий шаблон сайта подключает KaTeX и Google Analytics; они могут показывать ошибки сети офлайн и не требуются решателю. Проверка интерфейса без этих ресурсов входит в приёмку.

Браузер может очистить данные сайта при нехватке места или ручной очистке. После этого приложение необходимо открыть онлайн повторно. Отметки и настройки хранятся только на текущем устройстве.

## Хостинг

Нужен HTTPS (или `localhost` для проверки). Отдавайте:

- `.js` как JavaScript;
- `.webmanifest` как `application/manifest+json`;
- PNG с корректным типом изображения.

Для `/apps/gothic-locks-sw.js` рекомендуется `Cache-Control: no-cache`. Для хешированных `/_next/static/` допустим длительный кеш. Скрипт сборки создаёт дополнительный `out/apps/gothic-locks/index.html`: обычный файловый хостинг сможет обслуживать адрес с завершающим слешем без отдельного правила rewrite.

Не заменяйте настоящие ответы 404 на HTML для отсутствующих JS/CSS: это скрывает неполную загрузку ресурсов. При переносе всего сайта в подпапку потребуется согласовать `basePath`, URL манифеста, Worker и Service Worker; текущий вариант рассчитан на корень домена.

## Установка на Android

1. Откройте раздел в Chrome по HTTPS с интернетом.
2. Дождитесь подготовки офлайн.
3. В меню Chrome выберите «Установить приложение» или «Добавить на главный экран».
4. Запустите появившийся значок «Замки Gothic».
5. Для проверки включите авиарежим, закройте и вновь откройте приложение. Проверьте поиск, ручной расчёт и повторную загрузку.

Название пункта установки зависит от версии Chrome. Встроенные браузеры мессенджеров могут не предлагать установку.

## Проверки

```sh
node scripts/test-gothic-pwa.mjs
```

Тест проверяет созданный Worker, валидный и невалидный запрос, размеры PNG, связи манифеста, атомарную установку кеша, сохранность чужих кешей, перезагрузку приложения без сети и отсутствие перехвата посторонних страниц. Если уже создан `out/apps/gothic-locks-precache.json`, дополнительно проверяются реальные файлы экспорта и включение worker/core/иконок в кеш.

Этот автоматический тест моделирует Service Worker API в Node. Он не заменяет запуск Chrome на Android. Отдельная проверка в браузере: новая установка → готовность офлайн → отключение сети → перезагрузка → новый ручной расчёт → восстановление сети и обновление версии.

Иконки нарисованы специально для приложения простыми геометрическими фигурами; игровых изображений в них нет.

Технические ссылки: [область действия Service Worker](https://developer.mozilla.org/en-US/docs/Web/API/ServiceWorkerContainer/register), [офлайн-работа PWA](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Offline_and_background_operation).
