# Развёртывание после подтверждения владельца

Ветка: `codex/trophy-tracker`. На этапе разработки merge в `main`, production deploy и выполнение миграции в рабочем Supabase запрещены заданием и не выполнялись.

## Перед публикацией

1. Просмотреть diff ветки и миграцию `supabase/migrations/202610170001_trophy_events.sql`.
2. На отдельном тестовом Supabase применить миграцию через доверенный SQL Editor/CLI. Она добавляет только `public.trophy_events`, индексы, ограничения и RLS этой таблицы. Существующие таблицы и политики не меняются.
3. Убедиться, что Google OAuth настроен в существующем проекте Supabase, а тестовый origin и возврат на `/trophies`/`/trophies/gothic-remake` разрешены в Auth URL Configuration. Не расширять allowlist до произвольных внешних адресов.
4. Войти двумя разрешёнными тестовыми аккаунтами. Проверить отсутствие чужих записей. Одним аккаунтом войти на компьютере и телефоне, создать записи на обоих устройствах, сделать изменение офлайн, восстановить сеть и проверить совпадение прогресса. Сверить состояние PSN отдельно вручную.
5. Выполнить `npm ci`, `npx tsc --noEmit`, целевой lint, `npm run test:trophies`, `npm run test:trophies:sync`, `npm run test:gothic`, `npm run build`, браузерные проверки.

Клиент использует уже существующие публичные `NEXT_PUBLIC_SUPABASE_URL` и `NEXT_PUBLIC_SUPABASE_ANON_KEY`. Service-role ключ в браузере не нужен. Не добавлять его в `NEXT_PUBLIC_*`, исходники, экспорт или логи. Google и PSN пароли приложение не запрашивает.

## После отдельного разрешения на production

1. Сделать резервную копию рабочей БД и применить проверенную миграцию к правильному проекту.
2. Проверить RLS и Google redirect для `https://daos711.ru/trophies/gothic-remake`.
3. Слить проверенную ветку в `main`. Существующий GitHub Actions публикует статический каталог `out` при push в `main`; конфигурация деплоя здесь не изменена.
4. Проверить `/trophies`, `/trophies/gothic-remake`, `/trophies-sw.js`, manifest и обе иконки. Открыть Gothic Locks и убедиться в отдельном scope его worker.
5. Повторить короткую проверку входа, синхронизации телефона/ПК, офлайн-перезагрузки и установки на главный экран.

До применения миграции локальные отметки продолжат сохраняться, а синхронизация покажет ошибку отсутствующей таблицы/доступа. Это не означает потерю IndexedDB-данных. Не создавать второй аккаунт или очищать браузер для исправления этой ошибки.

## Откат

Откатить публикацию сайта на предыдущий коммит штатным механизмом. Не удалять новую таблицу и пользовательские журналы: append-only данные пригодятся при повторной публикации. Пользователь может предварительно сохранить JSON. Смена версии приложения не должна очищать IndexedDB или чужие PWA-кеши.
