## Что доказывают автоматические проверки

Движок пересчитывает следующий шаг после подтверждения, принимает произвольный порядок, различает неподтверждённые факты и реальные блокировки, не предлагает будущие главы при включении спойлеров, учитывает стадии книг и прекращает уверенные рекомендации при конфликте контекста. Проверяются циклы и противоречия графа. Реальные данные покрывают все 88 пунктов текущего сохранения и три отдельных действия вступления в лагеря.

Ветки копируют состояние персонажа без повторного начисления глобальных счётчиков. Переключение и восстановление журнала сохраняют глобальные трофеи. Выбор активной ветки независим для разных устройств. Импорт идемпотентен, неверный JSON не меняет прогресс. Многооперационные изменения атомарны; ошибка записи остаётся видимой. Автосохранение не поглощает удалённую правку, поступившую во время ввода, и восстанавливает черновик после ошибки/перезагрузки.

Обычная галочка урока или карты записывает статус текущего персонажа и общую историю одним действием. Снятие различает ошибочную отметку и загрузку старого сохранения: во втором случае история получения сохраняется. Групповая отмена восстанавливает прежние значения целиком, в том числе уже существовавшую запись истории; частичная отмена при ошибке не сохраняется.

Персональный набор содержит семь прежних уроков, четыре названные карты и пять вручную подтверждённых PSN-трофеев. У Бестиария Хориниса II отмечается только нахождение. Обновление существующего журнала добавляет подтверждённое в выбранное сохранение, сохраняет дополнительные отметки и заметки, не уменьшает большие счётчики и не заменяет иной выбранный план. Конфликтующие и неполные поля остаются для сверки; после разрешения расхождений незавершённое обновление можно повторить. Существующий журнал не обновляется при загрузке страницы автоматически.

SQL-тест выполняет 9 проверок ролей и ограничений по реальной миграции: владелец видит свои данные; другой владелец, anon и отсутствующий JWT subject — нет; подмена owner запрещена; UPDATE/DELETE запрещены; повторная вставка не перезаписывает данные; неверные payload отклоняются.

Интеграция синхронизации проверяет офлайн-очередь после перезапуска, сумму одновременных приращений, конфликт заметок и явное разрешение, потерянный ответ после COMMIT, пагинацию и смену аккаунта. Используются настоящий Supabase JS SDK и PostgreSQL/RLS, но OAuth и преобразование HTTP в локальный SQL — тестовые замены. Это не проверка рабочей Google-авторизации или двух физических устройств в production.

Предыдущий полный прогон обновлённого интерфейса и финальный повтор после правок заголовка и поведения «Отложить» для выбранного плана завершились успешно. Финальный прогон: **PASS, 6,37 с**. Артефакты: `%TEMP%\trophies-browser-WREQIL`; проверенная локальная PWA-сборка: `2beee66ab360d993`.

Полный сценарий покрывает:

- Три основные вкладки «Что дальше», «Мой прогресс», «Заметки» и дополнительные разделы в «Ещё».
- Начальный персональный набор: **7/46 уроков, 4 карты, 5 трофеев PSN**. Бестиарий Хориниса II только найден: передача, чтение, завершение поручения и новый урок не добавляются.
- Одну галочку карты: общий счётчик **4 → 5**, затем атомарную кнопку «Отменить»: **5 → 4**, с восстановлением состояния персонажа и истории.
- Явное обновление прежнего журнала кнопкой «Записать этот прогресс» с сохранением дополнительных отметок и пользовательских заметок.
- Собственный следующий план вступить в Старый лагерь, проверку условий и контрольную точку перед переходом главы; обычный следующий шаг, отмену, откладывание и произвольный порядок.
- Отказ записи IndexedDB при открытой контрольной точке: ошибка остаётся видимой, окно не закрывается как после успешного сохранения.
- Отдельную ветку сохранения и сохранность глобального трофея после возврата, перезагрузку выбранного прохождения и независимый второй браузерный контекст.
- Соответствие интерфейса 41 трофею и 46 урокам, автосохранение заметки и аварийный черновик, JSON roundtrip.
- Мобильные ширины **320 и 390 пикселей** без горизонтального переполнения, а также офлайн-переход из каталога в игру.

Отдельный PWA-тест проверяет scope `/trophies`, полную атомарную установку, ожидание явного обновления, сохранение IndexedDB и чужих кешей. В CacheStorage нет приватных API/OAuth-ответов. Открытые вкладки не теряют старые chunks при обновлении.

## Воспроизведение

```sh
npm ci
npx tsc --noEmit
npx eslint src/app/trophies src/lib/trophies scripts/build-trophies.mjs scripts/test-trophies-*.mjs
npm run test:trophies
npm run test:trophies:sync
npm run test:gothic
npm run build
```

Для Chromium укажите `PLAYWRIGHT_MODULE` и `CHROMIUM_PATH` на установленный Playwright и браузер. Без них встроенный реальный PWA-сценарий явно помечается skipped; остальные тесты выполняются. Браузерный скрипт требует оба пути и работающий статический сервер каталога `out` на localhost; `TROPHIES_TEST_URL` позволяет задать адрес (по умолчанию `http://127.0.0.1:8765`). Скрипт выводит путь к временному отчёту, JSON-экспорту и скриншотам, не отправляя их в production.
