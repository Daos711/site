- `git diff --check` — без ошибок пробелов.

## Что доказывают автоматические проверки

Движок пересчитывает следующий шаг после подтверждения, принимает произвольный порядок, различает неподтверждённые факты и реальные блокировки, не предлагает будущие главы при включении спойлеров, учитывает стадии книг и прекращает уверенные рекомендации при конфликте контекста. Проверяются циклы и противоречия графа. Реальные данные покрывают все 88 пунктов текущего сохранения и три отдельных действия вступления в лагеря.

Ветки копируют состояние персонажа без повторного начисления глобальных счётчиков. Переключение и восстановление журнала сохраняют глобальные трофеи. Выбор активной ветки независим для разных устройств. Импорт идемпотентен, неверный JSON не меняет прогресс. Многооперационные изменения атомарны; ошибка записи остаётся видимой. Автосохранение не поглощает удалённую правку, поступившую во время ввода, и восстанавливает черновик после ошибки/перезагрузки.

SQL-тест выполняет 9 проверок ролей и ограничений по реальной миграции: владелец видит свои данные; другой владелец, anon и отсутствующий JWT subject — нет; подмена owner запрещена; UPDATE/DELETE запрещены; повторная вставка не перезаписывает данные; неверные payload отклоняются.

Интеграция синхронизации проверяет офлайн-очередь после перезапуска, сумму одновременных приращений, конфликт заметок и явное разрешение, потерянный ответ после COMMIT, пагинацию и смену аккаунта. Используются настоящий Supabase JS SDK и PostgreSQL/RLS, но OAuth и преобразование HTTP в локальный SQL — тестовые замены. Это не проверка рабочей Google-авторизации или двух физических устройств в production.

## Браузер

`scripts/test-trophies-browser.mjs` запускает настоящий Chromium только против localhost и блокирует внешнюю сеть. Проверяет уточнённый личный preset 7/46 уроков и расхождение 1/3 названных карт; следующий шаг, отмену и откладывание; произвольный порядок; контрольную точку главы; отдельную ветку и сохранение трофея после возврата; соответствие интерфейса 41 трофею и 46 урокам; автосохранение заметки и аварийный черновик; JSON roundtrip; перезагрузку выбранного прохождения; независимый второй браузерный контекст; офлайн-переход каталог → игра. Проверены ширины 320 и 390 пикселей без горизонтального переполнения.

Отдельный PWA-тест проверяет scope `/trophies`, полную атомарную установку, ожидание явного обновления, сохранение IndexedDB и чужих кешей. В CacheStorage нет приватных API/OAuth-ответов. Открытые вкладки не теряют старые chunks при обновлении.

## Воспроизведение

```sh
npm ci
npx tsc --noEmit
npx eslint src/app/trophies src/lib/trophies scripts/build-trophies.mjs scripts/test-trophies-*.mjs
npm run test:trophies
npm run test:trophies:sync
npm run test:gothic
npm run build
```

Для Chromium укажите `PLAYWRIGHT_MODULE` и `CHROMIUM_PATH` на установленный Playwright и браузер. Без них встроенный реальный PWA-сценарий явно помечается skipped; остальные тесты выполняются. Браузерный скрипт требует оба пути и работающий статический сервер каталога `out` на localhost; `TROPHIES_TEST_URL` позволяет задать адрес (по умолчанию `http://127.0.0.1:8765`). Скрипт выводит путь к временному отчёту, JSON-экспорту и скриншотам, не отправляя их в production.

## Оставшаяся проверка перед публикацией

После разрешения владельца и применения миграции в тестовом Supabase нужны настоящий Google-вход, два тестовых аккаунта и физические телефон/ПК. Шаги даны в [DEPLOYMENT.md](./DEPLOYMENT.md). Игровые действия и спорные условия также требуют сверки с текущей PS5-версией игры; вычисленная доступность не выдаётся за собственную проверку в игре.
